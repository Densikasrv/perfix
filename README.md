# Perfix — сборка ОС

Perfix — экспериментальная 32-битная операционная система для архитектуры x86, написанная на Rust без стандартной библиотеки (`no_std`). Загрузка выполняется через GRUB с использованием Multiboot 1.

Это руководство описывает сборку и запуск Perfix на Linux с использованием Arch-based дистрибутива, Rust nightly, GRUB и QEMU.

## 1. Требования

Для сборки потребуются:

- Linux x86-64
- Rust и Cargo через rustup
- Rust nightly и компонент `rust-src`
- NASM
- GNU binutils
- GRUB и `grub-mkrescue`
- xorriso
- QEMU с поддержкой i386

В Arch-based дистрибутиве установите необходимые системные инструменты через `pacman`. Названия пакетов QEMU и GRUB могут зависеть от состава репозиториев:

```bash
sudo pacman -S --needed rustup rust-src nasm binutils grub xorriso
```

Установите QEMU, если он ещё не установлен, выбрав пакет с поддержкой системной эмуляции i386.

Если системный пакет Rust конфликтует с rustup, не устанавливайте их вслепую одновременно: используйте одну согласованную установку Rust.

## 2. Настройка Rust

Установите nightly toolchain:

```bash
rustup toolchain install nightly
rustup component add rust-src --toolchain nightly
```

Проверьте установку:

```bash
rustc +nightly --version
cargo +nightly --version
```

Perfix использует собственную конфигурацию цели `kernel/i686-perfix.json`, поэтому для сборки применяется nightly Cargo с флагом `-Z json-target-spec`.

## 3. Получение исходников

Клонируйте репозиторий:

```bash
git clone https://github.com/Densikasrv/perfix
cd perfix
```

Посмотрите структуру проекта:

boot/ — загрузочный код на ассемблере.

kernel/src/ — исходный код ядра на Rust.

kernel/linker.ld — сценарий компоновщика.

kernel/i686-perfix.json — конфигурация цели компиляции.

pdesk/ — графическая оболочка Perfix (отдельный crate, подключается к ядру как path-зависимость).

build/ — каталог для сборочных артефактов.

4. Сборка ОС

Все шаги сборки выполняет скрипт tools/build-iso.sh: он собирает объектные файлы загрузчика через NASM, собирает ядро nightly-компилятором с -Z build-std=core и создаёт ISO через grub-mkrescue.

bash tools/build-iso.sh

Готовый образ появится в build/perfix-min.iso. Скрипт сам подставляет абсолютные пути в RUSTFLAGS, поэтому каталог репозитория может быть любым, а запускать его можно из любой директории.

Ручная сборка

Соберите объектные файлы загрузчика:

mkdir -p kernel/target
nasm -f elf32 boot/boot.asm -o kernel/target/boot.o
nasm -f elf32 boot/gdt.asm -o kernel/target/boot-gdt.o
nasm -f elf32 boot/idt.asm -o kernel/target/boot-idt.o
nasm -f elf32 boot/exec.asm -o kernel/target/boot-exec.o

Затем задайте RUSTFLAGS и соберите ядро (пример для bash, из корня репозитория):

export RUSTFLAGS="-C link-arg=-T$PWD/kernel/linker.ld -C link-arg=-m -C link-arg=elf_i386 -C link-arg=$PWD/kernel/target/boot.o -C link-arg=$PWD/kernel/target/boot-gdt.o -C link-arg=$PWD/kernel/target/boot-idt.o -C link-arg=$PWD/kernel/target/boot-exec.o"

cargo +nightly build --manifest-path kernel/Cargo.toml -Z build-std=core -Z json-target-spec --target kernel/i686-perfix.json

Учтите: RUSTFLAGS содержит абсолютные пути, вычисленные через $PWD, поэтому команды нужно выполнять из корня репозитория. В fish многострочная вставка без обратного слэша ломается на отдельные команды — используйте одну строку или запускайте скрипт. В свежих nightly флаг -Z json-target-spec удалён; если cargo сообщает о неизвестном флаге, уберите его.

При успешной сборке ELF-файл ядра появится по пути:

kernel/target/i686-perfix/debug/perfix

5. Создание загрузочного ISO

Скрипт tools/build-iso.sh выполняет это автоматически. Вручную шаги выглядят так:

mkdir -p build/iso/boot/grub
cp kernel/target/i686-perfix/debug/perfix build/iso/boot/perfix.elf

Файл build/iso/boot/grub/grub.cfg с конфигурацией загрузки через Multiboot 1:

set timeout=0
set default=0

menuentry "Perfix" {
    multiboot /boot/perfix.elf
    boot
}

Создание ISO:

grub-mkrescue --modules="multiboot" --fonts="" --locales="" --themes="" -o build/perfix-min.iso -d /usr/lib/grub/i386-pc build/iso

Готовый образ будет находиться в build/perfix-min.iso.

6. Запуск в QEMU

Консоль по умолчанию использует VBE-режим 1024×768×32 (128×48 знакомест при шрифте 8×16). В меню GRUB можно выбрать 1920×1080×32, 800×600×32 или VGA text mode 80×25. Небольшое разрешение по умолчанию выбрано для совместимости со старыми видеокартами и мониторами: например, Dell Optiplex GX1 (ATI Rage Pro, 1999) не принимает 1920×1080 и показывает «Вне диапазона». Если выбранный режим недоступен, ядро автоматически переходит в VGA text mode 80×25. Установщик пишет меню в `/boot/grub/grub.cfg`, поэтому варианты режимов доступны и на установленной системе. В VirtualBox нижние 3 строки не используются (фактически 128×45), чтобы приглашение не уходило под край окна.

Запустить ядро без дополнительного тестового диска можно так:

qemu-system-i386 \
    -cdrom build/perfix-min.iso \
    -m 16M

Если прошивка не начинает загрузку с ISO автоматически, укажите порядок загрузки:

qemu-system-i386 \
    -cdrom build/perfix-min.iso \
    -boot order=d \
    -m 16M

Для проверки ATA и экспериментальной работы с exFAT подключите тестовый образ диска:

qemu-system-i386 \
    -drive file=build/perfix-disk.img,format=raw,if=ide,index=0 \
    -cdrom build/perfix-min.iso \
    -boot order=d \
    -m 16M

Образ build/perfix-disk.img используется для тестирования дисковых операций. Он не требуется для обычной загрузки ядра.

Несколько IDE-дисков и SATA удобно проверять на контроллере AHCI:

qemu-system-i386 \
    -device ich9-ahci \
    -drive if=none,id=d0,file=build/disk0.img,format=raw \
    -device ide-hd,drive=d0,bus=ide.0,unit=0 \
    -drive if=none,id=d1,file=build/disk1.img,format=raw \
    -device ide-hd,drive=d1,bus=ide.0,unit=1 \
    -drive if=none,id=s0,file=build/sata0.img,format=raw \
    -device ide-hd,drive=s0,bus=ide.2 \
    -drive if=none,id=cd,file=build/perfix-min.iso,media=cdrom \
    -device ide-cd,drive=cd,bus=ide.4 \
    -boot order=d \
    -m 16M

Шины ide.0 и ide.1 принадлежат встроенному PIIX3 IDE (по два устройства), а ide.2…ide.7 — портам контроллера AHCI. Опция -cdrom занимает ide.1 unit 0, поэтому при четырёх IDE-дисках CD-ROM нужно явно перенести на свободную шину, например ide.4.

USB 2.0 удобно проверить на контроллере EHCI с companion-контроллерами UHCI:

qemu-system-i386 \
    -device ich9-usb-ehci1,id=ehci \
    -device ich9-usb-uhci1,masterbus=ehci.0,firstport=0 \
    -device ich9-usb-uhci2,masterbus=ehci.0,firstport=2 \
    -device ich9-usb-uhci3,masterbus=ehci.0,firstport=4 \
    -device usb-kbd,bus=ehci.0 \
    -device usb-mouse,bus=ehci.0 \
    -device ich9-ahci \
    -drive if=none,id=cd,file=build/perfix-min.iso,media=cdrom \
    -device ide-cd,drive=cd,bus=ide.4 \
    -boot order=d \
    -m 16M

По умолчанию QEMU подключает usb-kbd и usb-mouse как high-speed, и их обслуживает EHCI. Чтобы проверить передачу портов companion-контроллерам, добавьте usb_version=1: устройства станут full-speed, EHCI выставит Port Owner, а клавиатуру и мышь перечислит соответствующий UHCI.

OHCI удобно проверить эмулятором Apple USB Controller:

qemu-system-i386 \
    -device pci-ohci,id=ohci \
    -device usb-kbd,bus=ohci.0 \
    -device usb-mouse,bus=ohci.0 \
    -cdrom build/perfix-min.iso \
    -boot order=d \
    -m 16M

QEMU подключает оба устройства как full-speed, и Perfix перечисляет их через OHCI. Именно такую схему использует MacBook Pro 2010 для встроенных клавиатуры и тачпада.

16 МиБ RAM достаточно для консоли, pdesk/pterm и запуска статических glibc-программ: буфер ELF-файла и стек программы выделяются из свободной памяти только на время запуска, куча программы отображается по мере роста `brk`, а отладочные секции не попадают в загрузочный образ. При 8 МиБ консоль и небольшие программы тоже работают, но запас памяти почти исчерпан, поэтому для полноценной работы рекомендуется не меньше 16 МиБ. В консольном режиме при 7 МиБ RAM (около 6 МиБ; часть нижней памяти занимает GRUB) работают оболочка, Perfbrowse и установка небольших пакетов pfpak.

7. Возможности ОС

В текущей экспериментальной версии реализованы:

Загрузка через GRUB и Multiboot 1.

Вывод текста в framebuffer-консоль: 128×48 знакомест в режиме по умолчанию 1024×768×32 и до 240×67 в 1920×1080×32 (шрифт 8×16). Поддерживаются 32-, 24- и 16-битные режимы: основной пункт меню GRUB автоматически выбирает первый доступный из списка 1024×768×32 → 1024×768×24 → 1024×768×16 → 800×600×…, а отдельные пункты позволяют явно выбрать 16-битный режим. Это нужно старым VBE-адаптерам, которые не умеют 32 бита на пиксель. При недоступности графики используется VGA text mode 80×25. Перед инициализацией VGA ядро пытается включить write-combining для области framebuffer через MTRR: на реальном железе (например, Intel 915GM) BIOS оставляет видеопамять некэшируемой, из-за чего перетаскивание окон в pdesk становится медленным. Если подходящего свободного диапазона MTRR нет или BIOS занял его несовместимым типом, настройка безопасно пропускается; команда mtrr показывает текущее состояние.

Обработка ввода с PS/2-клавиатуры.

Опрос PS/2-мыши: драйвер читает трёхбайтовые пакеты из контроллера i8042 (без прерываний) и сообщает координаты указателя и состояние кнопок. Команда mouse запускает демонстрацию драйвера.

USB-клавиатуры и мыши через UHCI (USB 1.1), OHCI (USB 1.1) и EHCI (USB 2.0). Драйвер опрашивает корневые порты всех найденных контроллеров, перечисляет устройства в HID boot protocol, а для интерфейсов без boot protocol разбирает их report descriptor, и поддерживает горячее подключение. Высокоскоростные устройства обслуживает EHCI, а порты с full/low-speed устройствами передаются companion-контроллерам UHCI или OHCI. USB-клавиатура использует те же раскладку и модификаторы, что и PS/2, а USB-мышь работает одновременно с PS/2; команда usb показывает состояние контроллеров, портов и счётчики ввода. Поддерживаются UHCI, OHCI и EHCI; xHCI не поддерживается. OHCI особенно важен для MacBook Pro 2010 (MacBookPro7,1) на чипсете NVIDIA: встроенные клавиатура и тачпад — full-speed USB-устройства на OHCI, поэтому без этого драйвера USB-ввод на такой машине не работает. Драйвер OHCI также перечисляет USB-хабы, включая вложенные, и поддерживает несколько HID-интерфейсов у одного устройства: на MacBook клавиатура и тачпад подключены через внутренние хабы, а тачпад является вторым интерфейсом того же устройства. Для хабов используются стандартные class-запросы (подача питания, сброс порта, статус порта), поэтому внешние хабы с full-speed устройствами тоже работают. Тачпад MacBook описан как HID-мышь без boot protocol, поэтому драйвер разбирает его report descriptor и находит номер отчёта, смещения кнопок и относительных координат — в обычном режиме тачпад работает как обычная мышь.

USB-стек также перечисляет устройства, для которых пока нет драйвера, и запоминает их VID/PID, класс и bulk-эндпоинты. В частности, Wi-Fi адаптер TL-WN727N на Realtek RTL8188EUS (`0bda:8179`) отображается в `usb` как `RTL8188EUS Wi-Fi (TL-WN727N)` вместе с адресами bulk IN/OUT и размером пакета. Для UHCI, OHCI и EHCI реализованы синхронные bulk-передачи, которые понадобятся драйверу Wi-Fi. Соединение по Wi-Fi на этом этапе не устанавливается: нужны прошивка `rtl8188eufw.bin`, инициализация PHY/RF, 802.11 и WPA2. Проверить детект можно только на реальном адаптере: QEMU не эмулирует RTL8188EUS, поэтому в эмуляторе проверяется generic-перечисление vendor-specific bulk-устройств (`usb-storage`).

Командная оболочка.

Текстовый редактор tedit: полноэкранная версия в духе GNU nano для консольной оболочки и GUI-версия в стиле «Блокнота» для pdesk.

GDT и IDT.

Обработчики исключений процессора.

Базовое включение paging с identity mapping первых 4 МиБ.

IDE/ATA PIO: оба канала (primary и secondary), master и slave, до четырёх дисков; адресация LBA28, команды IDENTIFY DEVICE, READ SECTORS, WRITE SECTORS и FLUSH CACHE.

Контроллер SATA/AHCI: поиск на шине PCI, регистры через BAR5 (MMIO), опрос до 32 портов без прерываний; команды IDENTIFY DEVICE, READ/WRITE DMA EXT и FLUSH CACHE. IDE- и SATA-диски собраны в общую таблицу блочных устройств, поэтому разделы, ext4/exFAT и установщик работают с любым из них.

Драйвер exFAT: монтирование тома, проверка контрольной суммы загрузочного региона, FAT-цепочки и NoFatChain, обход каталогов, чтение и запись файлов, создание и удаление каталогов по произвольному пути, обнаружение разделов exFAT в MBR, extended MBR и GPT.

Определение тома как на диске целиком, так и внутри раздела MBR.

Команды оболочки для работы с exFAT:

mount — параметры смонтированного тома (геометрия, серийный номер, флаги, контрольная сумма);

ls [путь] — список каталога, например ls / или ls SUBDIR;

cat <файл> — вывод содержимого файла (до 13 строк, с переносом длинных строк);

diskinfo — все найденные диски (IDE и SATA): модель, размер и разделы каждого;

write <файл> <текст> — создание или перезапись файла;

rm <файл> — удаление файла;

mkdir <каталог> — создание каталога;

rmdir <каталог> — удаление пустого каталога;

cd <каталог> — перейти в каталог;

pwd — показать текущий каталог;

listpart — разделы всех дисков (exFAT и ext4). Каждый раздел называется по физическому диску и своему номеру на нём: `/dsk/a1`, `/dsk/a2`, `/dsk/b1` (буква — диск, цифра — раздел). В скобках показан старый сквозной номер, который по-прежнему принимается командами. Диск, отформатированный в exFAT целиком, показывается как раздел 1; поддерживаются MBR, extended MBR и GPT;

cdpart <a1|n> — выбрать раздел по имени из listpart (`cdpart a1`) или по старому сквозному номеру и перейти в его корень; при загрузке ext4-раздел с установленной системой Perfix подключается автоматически (как и первый раздел exFAT), поэтому cdpart нужен только для остальных разделов;

fetch — сводка: OS, CPU, RAM и свободное место exFAT;

tedit <файл> — текстовый редактор: в консольной оболочке полноэкранный, а в pterm открывает GUI-версию в стиле «Блокнота»;

rootdir — псевдоним ls /, оставлен для совместимости;

mouse — демонстрация драйвера PS/2-мыши: координаты и кнопки обновляются, пока не нажата любая клавиша;

usb — состояние USB-контроллеров UHCI/OHCI/EHCI, корневых портов, подключённых клавиатуры и мыши, VID/PID и bulk-эндпоинтов остальных устройств (в том числе Wi-Fi адаптера RTL8188EUS), а также счётчики полученного ввода;

mtrr — состояние MTRR и диапазонов памяти: тип framebuffer (write-combining или uncached) и список переменных диапазонов (диагностика медленной перерисовки);

sata — состояние AHCI-контроллера: BAR, реализованные порты, подключённые ATA/ATAPI-устройства и общее число блочных устройств;

guinit — запустить графическую оболочку pdesk (только в framebuffer-режиме, после выхода управление возвращается в консольную оболочку);

exec <файл> — запустить сторонний 32-битный ELF-файл (статический ELF32 i386); псевдоним run;

lspci — список устройств PCI: адрес bus:slot.func, vendor:device, класс и IRQ; известные сетевые карты помечаются именами (RTL8139, e1000); псевдоним pci;

net — состояние сетевого интерфейса: модель карты, MAC, IP/маска, шлюз, DNS, состояние линка и счётчики принятых/переданных кадров;

ping <a.b.c.d> — отправить четыре ICMP-эхо и показать ответы и статистику;

pfpak — пакетный менеджер: list, info, install, remove, update, upgrade (см. раздел «Пакетный менеджер pfpak»);

elev <команда> — выполнить одну команду с правами суперпользователя; сначала запрашивается пароль суперпользователя. При удалении системных файлов после повышения прав выводится предупреждение `Do you know what you're doing? [Y/N]`;

install [n] [format] — установить Perfix на раздел с номером n из listpart; без аргумента выводит список разделов. Без слова format раздел должен быть ext4. Слово format сначала форматирует выбранный раздел в ext4 (все данные на нём стираются), после чего выполняет установку. Команда setup — псевдоним install;

mkfs.ext4 <n> — отформатировать раздел с номером n в ext4, создав пустую файловую систему с каталогом lost+found. Раздел должен быть обычным разделом MBR; контейнер расширенных разделов и GPT отклоняются;

timezone <GMT+N> — задать часовой пояс (смещение локального времени относительно RTC); часовой пояс применяется к часам в доке pdesk и к команде time;

time <dd/mm/yyyy/hh/mm/ss> — установить дату и время в текущем часовом поясе (значение пересчитывается в UTC и записывается в CMOS RTC).

Текущий каталог отображается в приглашении, например `perfix[EN] /docs> `. Команды принимают абсолютные и относительные пути; поддерживаются `.`, `..` и повторные `/`. `cd` без аргумента переходит в корень. Обычный пользователь может создавать, перезаписывать и удалять файлы только в своём домашнем каталоге `/home/<имя>` и в `/tmp`; для записи в системные пути требуется `elev`. Удалить можно только пустой каталог; непустой каталог и обычный файл защищены от неверных операций (rm не удаляет каталог, rmdir не удаляет файл, write не перезаписывает каталог). Тома с размером сектора, отличным от 512 байт, не поддерживаются. Регистр ASCII в именах не учитывается. Имена, содержащие не-ASCII символы, выводятся с символами ?. Каталоги не расширяются автоматически: когда в выделенном кластере заканчиваются свободные слоты, создание нового элемента возвращает `no free space`. Стрелки вверх/вниз листают историю последних 16 команд; набранный, но не выполненный текст сохраняется и возвращается при возврате из истории.

Пользователи и права

После установки учётные записи хранятся в `/etc/users`. Пароли не сохраняются в открытом виде: для каждого пароля генерируется соль и хранится только хеш. При загрузке установленной системы консольная оболочка запрашивает `login:` и `password:`; при неверных данных вход повторяется. pdesk отдельного входа не имеет и работает от имени пользователя, вошедшего в консоли.

Обычный пользователь может писать только в свой домашний каталог и `/tmp`. Системные файлы, включая `/perfix.elf`, защищены от записи и удаления. Команда `elev <команда>` запрашивает пароль суперпользователя, выполняет одну команду с полными правами и затем возвращает обычные права. Перед удалением системного файла после `elev` выводится предупреждение `Do you know what you're doing? [Y/N]`.

На установочном ISO входа нет: установщик работает от имени root, даже если на подключённом диске уже есть другая установка Perfix.

Запуск сторонних ELF-программ

Консольная оболочка и pterm умеют запускать сторонние программы командой `exec <файл>` (псевдоним `run <файл>`). Поддерживаются статические исполняемые файлы ELF32 для i386 с типом `ET_EXEC`. Динамически слинкованные файлы, PIE и программы другой архитектуры отклоняются с понятным сообщением.

Загрузчик проверяет ELF-заголовок, размещает сегменты `PT_LOAD` по их виртуальным адресам, обнуляет BSS и строит стек с `argc`/`argv`/`envp` и полным auxv, как при запуске в Linux. Затем управление передаётся точке входа. Программе доступно адресное пространство кучи размером 8 МиБ по адресу `0x40000000` для `brk` и TLS; физические страницы отображаются по мере роста `brk`, поэтому небольшая программа не занимает все 8 МиБ сразу. Системные вызовы Linux i386 выполняются через `int 0x80`: `exit`/`exit_group`, `write`, `writev`, `brk`, `uname`, `mprotect`, `set_thread_area`, `getpid`, `getuid`/`getgid`/`geteuid`/`getegid`; неизвестный вызов возвращает `-1`. Вывод программы попадает и в консоль, и в pterm.

Важно: программа выполняется в ring 0 без изоляции адресного пространства и TSS, поэтому это не песочница. Исключение CPU внутри программы перехватывается: выводится `exec: program crashed: exception ... at EIP ...`, после чего управление возвращается оболочке.

Процессоры без SSE поддерживаются: ядро и программы без SSE/AVX работают нормально, а `OSFXSR`/`OSXMMEXCPT` и XSAVE-состояние включаются только при наличии соответствующих возможностей у CPU (проверка через CPUID). FPU (x87) инициализируется при старте, если он есть. Если программа всё же выполнит SSE-инструкцию на CPU без SSE, ядро перехватит #UD и вернёт управление оболочке, как при любом другом исключении. Настройка MTRR для write-combining framebuffer тоже не требует SSE2: вместо `mfence` используется сериализующая инструкция `cpuid`, поэтому она работает и на Pentium II.

Примеры: `exec /hello`, `run /home/bob/program`.

Сеть

Первый сетевой драйвер — Realtek RTL8139 (включая RTL810x): карта работает в классическом режиме через порты ввода-вывода, приём идёт по кольцевому буферу, передача — через четыре дескриптора TSD. Прерывания не используются, драйвер опрашивает регистры из основного цикла, что подходит однопоточному ядру. Поверх драйвера реализован минимальный стек: Ethernet, ARP, IPv4, ICMP, UDP, DNS и TCP.

Параметры сети статические и рассчитаны на user-mode сеть QEMU: `10.0.2.15/24`, шлюз `10.0.2.2`, DNS `10.0.2.3`. Адреса внутри подсети получают кадры напрямую, остальные отправляются через шлюз (MAC шлюза в кадре, IP получателя — исходный), поэтому работают `ping 10.0.2.2` и `ping 1.1.1.1`. Команда `net` показывает адрес, состояние линка и счётчики кадров; `ping` разрешает адрес через ARP, отправляет четыре ICMP-эхо и печатает ответы со временем отклика в миллисекундах (`Reply from ... time=0.3 ms`) и статистику (`N packets transmitted, M received`).

Perfbrowse — простой текстовый браузер: `browse <url>` или `perfbrowse <url>`. Он разрешает DNS-имена (A-записи), открывает TCP-соединение, отправляет HTTP/1.0-запрос, читает ответ до закрытия соединения, поддерживает `Transfer-Encoding: chunked`, вырезает из HTML текст и печатает его с переносом по словам и прокруткой. Поддерживаются `http://`, имена без схемы, IP-адреса и порты, отличные от 80: например, `browse http://example.com/`. Схема в URL распознаётся без учёта регистра. Адреса `https://` открываются по TLS 1.3 (порт по умолчанию 443): клиент проверяет цепочку сертификатов до встроенного набора корневых CA, срок действия, имя/IP из subjectAltName и подпись CertificateVerify. Поддерживаются шифр `TLS_AES_128_GCM_SHA256`, обмен ключами X25519, подписи RSA (PKCS#1 v1.5 и PSS с SHA-256) и ECDSA P-256 (SHA-256). Ограничения: сертификаты на P-384/P-521 и подписи SHA-384/SHA-512 пока не поддерживаются (часть сайтов, например example.com, отклоняется с `tls: cert: cannot parse issuer`). Своего механизма повторной передачи в TCP нет, но в user-mode сети QEMU потери практически исключены. CSS, картинки, таблицы и переходы по ссылкам пока не поддерживаются; тело ответа и текст ограничены 32 КиБ.

В pdesk у Perfbrowse есть графическое окно (иконка `www` в доке): адресная строка, загрузка по Enter, прокрутка стрелками и PageUp/PageDown, Ctrl+L очищает адрес. Команда `browse <url>` в pterm открывает это окно с уже заполненным адресом.

Драйвер включается автоматически при загрузке, если `lspci` находит RTL8139/RTL810x; при отсутствии поддерживаемой карты команды сообщают `no network device`. Поддержка e1000 появится в следующих версиях.

Пакетный менеджер pfpak

pfpak работает поверх ext4-раздела с установленной системой. Пакеты распространяются как `.tar.gz`, а метаданные хранятся в текстовом `MANIFEST`. Список репозиториев задаётся в `/etc/pfpak/repo.list`, по одной записи на строку:

```text
http://example.com/perfix/pfpak RELEASE:fatcat
```

Первое поле — базовый URL, второе — релиз (префикс `RELEASE:` необязателен). Загрузка идёт по HTTP или HTTPS (TLS 1.3 с проверкой цепочки сертификатов до встроенных корневых CA). Для релиза `fatcat` и пакета `hello` используются пути:

```text
<url>/fatcat/hello/MANIFEST
<url>/fatcat/hello/hello-1.1.tar.gz
<url>/fatcat/INDEX              (необязательный, для update)
```

`MANIFEST` содержит поля `name`, `version`, `maintainer`, `description`, `size`, `depends` и список файлов после строки `files:`. Зависимости перечисляются через запятую. Установленный манифест сохраняется без изменений в `/etc/pfpak/InstalledPaks/<пакет>/MANIFEST`.

Репозиторий можно держать и на GitHub: файлы отдаёт `raw.githubusercontent.com`, цепочка сертификатов которого (RSA, SHA-256) поддерживается, поэтому в `repo.list` указывайте прямой raw-адрес:

```text
https://raw.githubusercontent.com/<владелец>/<репозиторий>/<ветка>/pfpak RELEASE:fatcat
```

Если скопировать адрес прямо из браузера GitHub (`.../<владелец>/<репозиторий>/tree/<ветка>/pfpak`), pfpak сам уберёт `/tree/` и обратится к raw-хосту. Именно такая запись создаётся установщиком по умолчанию:

```text
https://raw.githubusercontent.com/Densikasrv/pfpak-repo/tree/main/pfpak RELEASE:fatcat
```

Ссылку вида `https://github.com/<владелец>/<репозиторий>/raw/<ветка>/pfpak` использовать нельзя: `github.com` отвечает перенаправлением 302 на raw-хост, а HTTP-клиент ядра редиректы не выполняет (к тому же цепочка сертификатов `github.com` построена на P-384/SHA-384, что пока не поддерживается).

Команды:

- `pfpak list` — список установленных пакетов;
- `pfpak info <пакет>` — сведения об установленном или доступном в репозитории пакете;
- `elev pfpak install <пакет>` — установить пакет и его зависимости;
- `elev pfpak remove <пакет>` — удалить пакет; удаление блокируется, если от него зависят другие установленные пакеты;
- `elev pfpak update` — загрузить `INDEX` репозиториев в `/etc/pfpak/Cache`;
- `elev pfpak upgrade <пакет>` — обновить пакет до версии из репозитория;
- `elev pfpak upgrade all` — обновить все установленные пакеты.

Изменяющие команды требуют `elev`; `list` и `info` доступны обычному пользователю. Обновление пакета устанавливает поверх старых только файлы из нового архива: файлы, которых больше нет в манифесте, автоматически не удаляются.

Распаковка ограничена каталогами `/usr`, `/opt`, `/bin`, `/sbin`, `/lib`, `/etc`, `/var` и `/share`, а системные пути (`/etc/pfpak`, `/etc/users`, `/boot` и другие) защищены. Архив не может выйти за пределы разрешённых путей: отклоняются `..`, абсолютные и внешние ссылки, жёсткие ссылки и специальные файлы. Каждый файл архива должен быть перечислен в манифесте. Действуют ограничения на размер манифеста (16 КиБ), архива, отдельного файла (2 МиБ) и всего распакованного пакета (16 МиБ); при ошибке уже созданные файлы удаляются.

Системное ядро `/perfix.elf` защищено от обычных пакетов. Перезаписывать и удалять его разрешено только пакету с именем `perfix`, манифест которого указывает мейнтейнера `Densikasrv`; остальные пакеты получают ошибку `package writes outside allowed paths`, даже если совпадает имя или мейнтейнер по отдельности.

Редактор tedit

tedit открывает файл в полноэкранном режиме: строка заголовка, 64 строки текста, строка состояния и подсказка по клавишам. Длинные строки переносятся, курсор и экран прокручиваются. Отсутствующий файл открывается как новый.

Горячие клавиши:

Ctrl+O — сохранить файл (текст записывается в UTF-8);

Ctrl+X — выход; при наличии изменений редактор спрашивает Y/N, сохранять ли буфер;

Ctrl+K — вырезать текущую строку;

Ctrl+U — вставить вырезанную строку;

Ctrl+G — подсказка по клавишам;

стрелки, Home, End, PageUp, PageDown — перемещение курсора;

Backspace, Delete, Enter, Tab — редактирование (Tab вставляет четыре пробела).

Ограничения tedit: буфер 8 КиБ, поддерживаются символы CP866 (ASCII и русская кириллица); остальные символы при загрузке заменяются на ?.

В окне pterm команда tedit открывает графическую версию редактора: белое поле текста, строку меню (File, Edit, Format, View, Help), строку состояния с номером строки и столбца и полосу прокрутки — по виду как «Блокнот» Windows. Пункты меню кликабельны и открывают выпадающие списки: File — Save, Save As... (Ctrl+S) и Exit, Edit — Cut line и Paste, Format — включение и выключение переноса строк, View — показ строки состояния, Help — подсказка по клавишам и сведения о редакторе. Save As открывает диалог с полем «File name», где можно ввести абсолютный или относительный путь, например `/test/test.txt`; Enter сохраняет, Esc отменяет. Горячие клавиши те же, что у консольного tedit (Ctrl+O, Ctrl+X, Ctrl+K, Ctrl+U, Ctrl+G), курсор ставится и мышью. При закрытии окна с несохранёнными изменениями редактор спрашивает Y/N/Ctrl+C. Заголовок окна показывает имя файла и звёздочку при несохранённых изменениях. Команда tedit без аргумента открывает пустой документ `untitled`, который по Ctrl+O сохраняется в домашний каталог пользователя как `/home/<имя>/untitled`; диалог Save As также заранее заполняется домашним каталогом. Консольный tedit в самой оболочке (без pterm) по-прежнему работает в полноэкранном режиме.

fmgr — файловый менеджер в духе Thunar (иконка с жёлтой папкой в доке). Слева показаны разделы в новом формате `/dsk/a1`, `/dsk/a2`, `/dsk/b1`; щелчок по разделу открывает его корень. Справа — список файлов и каталогов с размерами, прокруткой и сортировкой (каталоги первыми). Навигация: стрелки, PageUp/PageDown, Enter — войти в каталог или открыть текст в tedit, Backspace или `u` — на уровень выше. Панель инструментов и горячие клавиши: `n` — создать каталог, `r` — переименовать, `d`/Delete — удалить (с подтверждением y/n), `c` — копировать, `x` — вырезать, `v` — вставить, `o`/Enter — открыть. Файлы можно копировать и переносить между разделами; каталоги переименовываются, если они пусты, а копирование каталогов пока не поддерживается. Двойной щелчок по строке также открывает файл или каталог. Пути `/dsk/a1/...` понимают также `tedit`, `cp`, `mv` и `exec`.

Графическая оболочка pdesk

pdesk — ранняя версия графической оболочки Perfix. Она собирается отдельным crate-ом в каталоге pdesk/ и не зависит от внутренностей ядра: всё взаимодействие идёт через трейт pdesk::Platform, который реализован в kernel/src/gui.rs поверх framebuffer-консоли, клавиатуры и PS/2-мыши.

Пока в оболочке есть рабочий стол, терминал pterm, графический браузер Perfbrowse, файловый менеджер fmgr, тетрис, змейка, редактор tedit и установщик Perfix, указатель мыши и док в стиле macOS. На уже установленной системе установщик скрыт из дока и меню. Каждое приложение открывается в своём окне: окна перетаскиваются за заголовок левой кнопкой, а справа в заголовке — кнопки в стиле Windows (свернуть, развернуть на весь экран / восстановить, закрыть). Активное окно получает клавиатуру и рисуется поверх остальных. Закрытое или свёрнутое окно открывается кликом по иконке приложения в доке или через меню перфоратора; при закрытии терминал начинает новую сессию. Выход из pdesk — Ctrl+Q, команда exit или пункт Exit to shell в меню дока; управление возвращается в консольную оболочку.

Размер окон подстраивается под разрешение framebufferа: при запуске окно не выходит за экран и не прячется под доком (на 800×600 pterm становится ниже и показывает столько строк, сколько помещается), а на больших разрешениях сохраняется привычный размер. Любое окно, кроме развёрнутого, можно растянуть или сжать мышью, потянув за его край или угол (полоса захвата — 5 пикселей). Содержимое подстраивается на лету: pterm и tedit пересчитывают число столбцов и строк, Perfbrowse заново переносит текст по ширине, fmgr перерисовывает списки. Минимальные размеры не дают сломать вёрстку: у игр и редактора — по размеру игрового поля и знакомест, у остальных приложений — по размеру панелей инструментов.

Док прижат к нижнему краю по центру и расширяется при добавлении приложений: его ширина считается по количеству иконок. Справа в доке показываются текущие время и дата из CMOS RTC (с учётом часового пояса, обновляются автоматически). Крайняя левая иконка — перфоратор (лончер): по нажатию над доком открывается меню со всеми GUI-приложениями (pterm, perfbrowse, fmgr, tetris, snake, tedit, install), кнопкой Shutdown (выключение через ACPI) и пунктом Exit to shell. Иконки и пункты меню подсвечиваются при наведении, клик мимо меню закрывает его, а перетаскивание окна начинается только за его заголовок.

Тетрис: поле 10x20, стрелки — движение и поворот, пробел или Enter — сброс фигуры, после проигрыша Enter начинает заново. Змейка в духе Nokia 3310: поле 20x20 на «LCD», стрелки задают направление, движение начинается с первой стрелки, после проигрыша — Enter.

pterm выполняет настоящие команды оболочки Perfix: help, version, fetch, ls, cat, write, rm, mkdir, rmdir, cd, pwd, calc, cp, mv, mount, diskinfo, listpart, cdpart и другие — код команд и файловых систем не дублируется в pdesk. Ядро запускает команду в виртуальной консоли 80x40 и передаёт её текст в окно (kernel/src/pterm.rs), а приглашение в pterm показывает активную раскладку и текущий каталог. `elev` работает и в pterm: после команды `elev pfpak install ...` терминал запрашивает пароль суперпользователя (символы маскируются звёздочками), выполняет одну команду с повышенными правами и возвращает обычное приглашение; неверный пароль выводит `elev: incorrect password`. На установочном ISO без учётных записей пароль не запрашивается.

Полноэкранные команды (mouse, divzero, pagefault, halt) получают настоящий экран целиком: оболочка временно убирает рабочий стол, после завершения команды pdesk перерисовывается. Команда tedit перехватывается окном и открывает GUI-редактор, поэтому консольный полноэкранный tedit в pterm не запускается; в консольной оболочке без pdesk он работает как раньше. Команда guinit из pterm запрещена, чтобы не запустить оболочку рекурсивно, а clear и exit обрабатываются самим окном.

Ранняя версия не запускается автоматически: в консольной оболочке введите guinit. Для запуска нужен линейный framebuffer (GRUB настраивает 1024×768, при необходимости 24 или 16 бит); в VGA text mode команда сообщает, что графика недоступна.

Установка на диск

Установочный ISO загружает в память три Multiboot-модуля: ядро perfix.elf, первый сектор GRUB boot.img и сгенерированный core.img. Установить Perfix можно из консоли командой install [n] [format] (псевдоним setup [n] [format]) или в pdesk через приложение install. Установщик спрашивает имя пользователя (1–16 символов), пароль пользователя и пароль суперпользователя, создаёт `/home/<имя>` и записывает хеши паролей в `/etc/users`. Кроме того, он создаёт `/etc/pfpak/repo.list` с репозиторием pfpak по умолчанию, добавляет в список установленных пакетов `perfix` версии 0.2.9 от `Densikasrv` с единственным файлом `/perfix.elf` (манифест в `/etc/pfpak/InstalledPaks/perfix/MANIFEST`) и записывает встроенные корневые сертификаты в `/etc/ssl/certs/ca-certificates.crt`, чтобы HTTPS работал и после загрузки с диска, а не только с ISO. После перезагрузки консольная оболочка запрашивает `login:` и `password:`, а pterm и tedit автоматически используют домашний каталог пользователя. Установщик копирует ядро в корень выбранного раздела как /perfix.elf, записывает boot.img в MBR и core.img сразу после MBR по LBA 1. Сигнатура диска и таблица разделов при этом сохраняются. core.img ищет /perfix.elf через search --file, поэтому номер раздела не зашивается в загрузчик.

Без слова format установка идёт только на существующий ext4-раздел. Явный флаг format (в pdesk — переключатель «Format as ext4») сначала создаёт на выбранном разделе новую ext4-ФС, стирая его содержимое, и только затем устанавливает Perfix. Отдельная команда mkfs.ext4 <n> форматирует раздел, не выполняя установку. Форматирование поддерживает разделы от нескольких мегабайт; для разделов меньше 8 МиБ используется размер блока 1 КиБ, иначе 4 КиБ.

Принимаются только MBR-диски: GPT (защитный MBR с типом 0xEE) отклоняется. Контейнер расширенных разделов нельзя ни установить как цель, ни отформатировать. Первый раздел должен начинаться после конца core.img — для обычного начала на LBA 2048 места достаточно; если промежуток после MBR меньше, установка не выполняется. Ядро записывается раньше загрузчика, чтобы ошибка на раннем этапе не испортила существующую загрузку.

После успешной установки на ext4-разделе создаётся файл /etc/InstallSuccess. При загрузке с диска (когда установочные Multiboot-модули отсутствуют) система проверяет этот маркер и убирает установщик из консоли (команды install и setup) и из pdesk (иконка и пункт меню install). На установочном ISO установщик остаётся доступным, даже если на подключённом диске уже есть Perfix.

Оболочку можно собрать отдельно от ядра и ISO:

```bash
cargo +nightly build --manifest-path pdesk/Cargo.toml \
    --target kernel/i686-perfix.json -Z build-std=core -Z json-target-spec
```

Результат — pdesk/target/i686-perfix/debug/libpdesk.rlib. При сборке ISO через tools/build-iso.sh ядро собирает pdesk автоматически как path-зависимость.

Проверка драйвера exFAT на хосте

Драйвер файловой системы вынесен в kernel/src/exfat/fs.rs и не зависит от ATA и VGA: доступ к диску выполняется через трейт BlockReader. Благодаря этому его можно проверять обычными тестами на хосте, подставляя образ диска в памяти. Тесты лежат в tools/exfat-check и компилируют тот же файл драйвера, что и ядро.

Запуск проверки:

cargo test --manifest-path tools/exfat-check/Cargo.toml

Тесты покрывают монтирование тома, определение раздела MBR, проверку контрольной суммы загрузочного региона, разбор наборов записей каталога, FAT-цепочки, режим NoFatChain, чтение и запись файлов, создание и удаление каталогов, защиту непустых каталогов и обработку повреждённых структур.



8. Ограничения

Perfix — учебный проект, а не готовая операционная система общего назначения.

Основной проверенной средой запуска является QEMU. Совместимость с реальным оборудованием, включая старые процессоры, необходимо проверять отдельно.

Перед экспериментами с реальными накопителями используйте тестовые образы и резервные копии.

Установщик работает только с MBR-дисками, требует свободного промежутка после MBR для core.img и изменяет MBR, поэтому на реальном накопителе с другой загрузочной записью его нужно применять осознанно. Форматирование (install ... format или mkfs.ext4) необратимо уничтожает данные выбранного раздела.
