# Perfix — сборка ОС

Perfix — экспериментальная 32-битная операционная система для архитектуры x86, написанная на Rust без стандартной библиотеки (`no_std`). Загрузка выполняется через GRUB с использованием Multiboot 1.

Это руководство описывает сборку и запуск Perfix на Linux с использованием Arch-based дистрибутива, Rust nightly, GRUB и QEMU.

## 1. Требования

Для сборки потребуются:

- Linux x86-64
- Rust и Cargo через rustup
- Rust nightly и компонент `rust-src`
- NASM
- GNU binutils
- GRUB и `grub-mkrescue`
- xorriso
- QEMU с поддержкой i386

В Arch-based дистрибутиве установите необходимые системные инструменты через `pacman`. Названия пакетов QEMU и GRUB могут зависеть от состава репозиториев:

```bash
sudo pacman -S --needed rustup rust-src nasm binutils grub xorriso
```

Установите QEMU, если он ещё не установлен, выбрав пакет с поддержкой системной эмуляции i386.

Если системный пакет Rust конфликтует с rustup, не устанавливайте их вслепую одновременно: используйте одну согласованную установку Rust.

## 2. Настройка Rust

Установите nightly toolchain:

```bash
rustup toolchain install nightly
rustup component add rust-src --toolchain nightly
```

Проверьте установку:

```bash
rustc +nightly --version
cargo +nightly --version
```

Perfix использует собственную конфигурацию цели `kernel/i686-perfix.json`, поэтому для сборки применяется nightly Cargo с флагом `-Z json-target-spec`.

## 3. Получение исходников

Клонируйте репозиторий:

```bash
git clone https://github.com/Densikasrv/perfix
cd perfix
```

Посмотрите структуру проекта:

boot/ — загрузочный код на ассемблере.

kernel/src/ — исходный код ядра на Rust.

kernel/linker.ld — сценарий компоновщика.

kernel/i686-perfix.json — конфигурация цели компиляции.

build/ — каталог для сборочных артефактов.

4. Сборка ОС

Все шаги сборки выполняет скрипт tools/build-iso.sh: он собирает объектные файлы загрузчика через NASM, собирает ядро nightly-компилятором с -Z build-std=core и создаёт ISO через grub-mkrescue.

bash tools/build-iso.sh

Готовый образ появится в build/perfix-min.iso. Скрипт сам подставляет абсолютные пути в RUSTFLAGS, поэтому каталог репозитория может быть любым, а запускать его можно из любой директории.

Ручная сборка

Соберите объектные файлы загрузчика:

mkdir -p kernel/target
nasm -f elf32 boot/boot.asm -o kernel/target/boot.o
nasm -f elf32 boot/gdt.asm -o kernel/target/boot-gdt.o
nasm -f elf32 boot/idt.asm -o kernel/target/boot-idt.o

Затем задайте RUSTFLAGS и соберите ядро (пример для bash, из корня репозитория):

export RUSTFLAGS="-C link-arg=-T$PWD/kernel/linker.ld -C link-arg=-m -C link-arg=elf_i386 -C link-arg=$PWD/kernel/target/boot.o -C link-arg=$PWD/kernel/target/boot-gdt.o -C link-arg=$PWD/kernel/target/boot-idt.o"

cargo +nightly build --manifest-path kernel/Cargo.toml -Z build-std=core -Z json-target-spec --target kernel/i686-perfix.json

Учтите: RUSTFLAGS содержит абсолютные пути, вычисленные через $PWD, поэтому команды нужно выполнять из корня репозитория. В fish многострочная вставка без обратного слэша ломается на отдельные команды — используйте одну строку или запускайте скрипт. В свежих nightly флаг -Z json-target-spec удалён; если cargo сообщает о неизвестном флаге, уберите его.

При успешной сборке ELF-файл ядра появится по пути:

kernel/target/i686-perfix/debug/perfix

5. Создание загрузочного ISO

Скрипт tools/build-iso.sh выполняет это автоматически. Вручную шаги выглядят так:

mkdir -p build/iso/boot/grub
cp kernel/target/i686-perfix/debug/perfix build/iso/boot/perfix.elf

Файл build/iso/boot/grub/grub.cfg с конфигурацией загрузки через Multiboot 1:

set timeout=0
set default=0

menuentry "Perfix" {
    multiboot /boot/perfix.elf
    boot
}

Создание ISO:

grub-mkrescue --modules="multiboot" --fonts="" --locales="" --themes="" -o build/perfix-min.iso -d /usr/lib/grub/i386-pc build/iso

Готовый образ будет находиться в build/perfix-min.iso.

6. Запуск в QEMU

Консоль использует VBE-режим 1920×1080×32, который GRUB включает через Multiboot и `gfxpayload`; это даёт 240×67 знакомест при шрифте 8×16. Если режим недоступен, ядро автоматически переходит в VGA text mode 80×25. В VirtualBox нижние 3 строки не используются (фактически 240×64), чтобы приглашение не уходило под край окна.

Запустить ядро без дополнительного тестового диска можно так:

qemu-system-i386 \
    -cdrom build/perfix-min.iso \
    -m 128M

Если прошивка не начинает загрузку с ISO автоматически, укажите порядок загрузки:

qemu-system-i386 \
    -cdrom build/perfix-min.iso \
    -boot order=d \
    -m 128M

Для проверки ATA и экспериментальной работы с exFAT подключите тестовый образ диска:

qemu-system-i386 \
    -drive file=build/perfix-disk.img,format=raw,if=ide,index=0 \
    -cdrom build/perfix-min.iso \
    -boot order=d \
    -m 128M

Образ build/perfix-disk.img используется для тестирования дисковых операций. Он не требуется для обычной загрузки ядра.

7. Возможности ОС

В текущей экспериментальной версии реализованы:

Загрузка через GRUB и Multiboot 1.

Вывод текста в framebuffer-консоль 240×67 (VBE 1920×1080×32, шрифт 8×16); при недоступности режима используется VGA text mode 80×25.

Обработка ввода с PS/2-клавиатуры.

Командная оболочка.

Полноэкранный текстовый редактор tedit в духе GNU nano.

GDT и IDT.

Обработчики исключений процессора.

Базовое включение paging с identity mapping первых 4 МиБ.

Чтение секторов ATA PIO.

Драйвер exFAT: монтирование тома, проверка контрольной суммы загрузочного региона, FAT-цепочки и NoFatChain, обход каталогов, чтение и запись файлов, создание и удаление каталогов по произвольному пути, обнаружение разделов exFAT в MBR, extended MBR и GPT.

Определение тома как на диске целиком, так и внутри раздела MBR.

Команды оболочки для работы с exFAT:

mount — параметры смонтированного тома (геометрия, серийный номер, флаги, контрольная сумма);

ls [путь] — список каталога, например ls / или ls SUBDIR;

cat <файл> — вывод содержимого файла (до 13 строк, с переносом длинных строк);

diskinfo — поля загрузочного сектора exFAT;

write <файл> <текст> — создание или перезапись файла;

rm <файл> — удаление файла;

mkdir <каталог> — создание каталога;

rmdir <каталог> — удаление пустого каталога;

cd <каталог> — перейти в каталог;

pwd — показать текущий каталог;

listpart — список найденных разделов exFAT с LBA и размером;

cdpart <n> — выбрать раздел exFAT по номеру из listpart и перейти в его корень;

fetch — сводка: OS, CPU, RAM и свободное место exFAT;

tedit <файл> — полноэкранный текстовый редактор;

rootdir — псевдоним ls /, оставлен для совместимости.

Текущий каталог отображается в приглашении, например `perfix[EN] /docs> `. Команды принимают абсолютные и относительные пути; поддерживаются `.`, `..` и повторные `/`. `cd` без аргумента переходит в корень. Файлы и каталоги можно создавать, перезаписывать и удалять в любом существующем каталоге. Удалить можно только пустой каталог; непустой каталог и обычный файл защищены от неверных операций (rm не удаляет каталог, rmdir не удаляет файл, write не перезаписывает каталог). Тома с размером сектора, отличным от 512 байт, не поддерживаются. Регистр ASCII в именах не учитывается. Имена, содержащие не-ASCII символы, выводятся с символами ?. Каталоги не расширяются автоматически: когда в выделенном кластере заканчиваются свободные слоты, создание нового элемента возвращает `no free space`. Стрелки вверх/вниз листают историю последних 16 команд; набранный, но не выполненный текст сохраняется и возвращается при возврате из истории.

Редактор tedit

tedit открывает файл в полноэкранном режиме: строка заголовка, 64 строки текста, строка состояния и подсказка по клавишам. Длинные строки переносятся, курсор и экран прокручиваются. Отсутствующий файл открывается как новый.

Горячие клавиши:

Ctrl+O — сохранить файл (текст записывается в UTF-8);

Ctrl+X — выход; при наличии изменений редактор спрашивает Y/N, сохранять ли буфер;

Ctrl+K — вырезать текущую строку;

Ctrl+U — вставить вырезанную строку;

Ctrl+G — подсказка по клавишам;

стрелки, Home, End, PageUp, PageDown — перемещение курсора;

Backspace, Delete, Enter, Tab — редактирование (Tab вставляет четыре пробела).

Ограничения tedit: буфер 8 КиБ, поддерживаются символы CP866 (ASCII и русская кириллица); остальные символы при загрузке заменяются на ?.

Проверка драйвера exFAT на хосте

Драйвер файловой системы вынесен в kernel/src/exfat/fs.rs и не зависит от ATA и VGA: доступ к диску выполняется через трейт BlockReader. Благодаря этому его можно проверять обычными тестами на хосте, подставляя образ диска в памяти. Тесты лежат в tools/exfat-check и компилируют тот же файл драйвера, что и ядро.

Запуск проверки:

cargo test --manifest-path tools/exfat-check/Cargo.toml

Тесты покрывают монтирование тома, определение раздела MBR, проверку контрольной суммы загрузочного региона, разбор наборов записей каталога, FAT-цепочки, режим NoFatChain, чтение и запись файлов, создание и удаление каталогов, защиту непустых каталогов и обработку повреждённых структур.



8. Ограничения

Perfix — учебный проект, а не готовая операционная система общего назначения.

Основной проверенной средой запуска является QEMU. Совместимость с реальным оборудованием, включая старые процессоры, необходимо проверять отдельно.

Перед экспериментами с реальными накопителями используйте тестовые образы и резервные копии.
