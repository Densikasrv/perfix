# Perfix — сборка ОС

Perfix — экспериментальная 32-битная операционная система для архитектуры x86, написанная на Rust без стандартной библиотеки (`no_std`). Загрузка выполняется через GRUB с использованием Multiboot 1.

Это руководство описывает сборку и запуск Perfix на Linux с использованием Arch-based дистрибутива, Rust nightly, GRUB и QEMU.

## 1. Требования

Для сборки потребуются:

- Linux x86-64
- Rust и Cargo через rustup
- Rust nightly и компонент `rust-src`
- NASM
- GNU binutils
- GRUB и `grub-mkrescue`
- xorriso
- QEMU с поддержкой i386

В Arch-based дистрибутиве установите необходимые системные инструменты через `pacman`. Названия пакетов QEMU и GRUB могут зависеть от состава репозиториев:

```bash
sudo pacman -S --needed rustup rust-src nasm binutils grub xorriso
```

Установите QEMU, если он ещё не установлен, выбрав пакет с поддержкой системной эмуляции i386.

Если системный пакет Rust конфликтует с rustup, не устанавливайте их вслепую одновременно: используйте одну согласованную установку Rust.

## 2. Настройка Rust

Установите nightly toolchain:

```bash
rustup toolchain install nightly
rustup component add rust-src --toolchain nightly
```

Проверьте установку:

```bash
rustc +nightly --version
cargo +nightly --version
```

Perfix использует собственную конфигурацию цели `kernel/i686-perfix.json`, поэтому для сборки применяется nightly Cargo с флагом `-Z json-target-spec`.

## 3. Получение исходников

Клонируйте репозиторий:

```bash
git clone https://github.com/Densikasrv/perfix
cd perfix
```

Посмотрите структуру проекта:

boot/ — загрузочный код на ассемблере.

kernel/src/ — исходный код ядра на Rust.

kernel/linker.ld — сценарий компоновщика.

kernel/i686-perfix.json — конфигурация цели компиляции.

pdesk/ — графическая оболочка Perfix (отдельный crate, подключается к ядру как path-зависимость).

build/ — каталог для сборочных артефактов.

4. Сборка ОС

Все шаги сборки выполняет скрипт tools/build-iso.sh: он собирает объектные файлы загрузчика через NASM, собирает ядро nightly-компилятором с -Z build-std=core и создаёт ISO через grub-mkrescue.

bash tools/build-iso.sh

Готовый образ появится в build/perfix-min.iso. Скрипт сам подставляет абсолютные пути в RUSTFLAGS, поэтому каталог репозитория может быть любым, а запускать его можно из любой директории.

Ручная сборка

Соберите объектные файлы загрузчика:

mkdir -p kernel/target
nasm -f elf32 boot/boot.asm -o kernel/target/boot.o
nasm -f elf32 boot/gdt.asm -o kernel/target/boot-gdt.o
nasm -f elf32 boot/idt.asm -o kernel/target/boot-idt.o

Затем задайте RUSTFLAGS и соберите ядро (пример для bash, из корня репозитория):

export RUSTFLAGS="-C link-arg=-T$PWD/kernel/linker.ld -C link-arg=-m -C link-arg=elf_i386 -C link-arg=$PWD/kernel/target/boot.o -C link-arg=$PWD/kernel/target/boot-gdt.o -C link-arg=$PWD/kernel/target/boot-idt.o"

cargo +nightly build --manifest-path kernel/Cargo.toml -Z build-std=core -Z json-target-spec --target kernel/i686-perfix.json

Учтите: RUSTFLAGS содержит абсолютные пути, вычисленные через $PWD, поэтому команды нужно выполнять из корня репозитория. В fish многострочная вставка без обратного слэша ломается на отдельные команды — используйте одну строку или запускайте скрипт. В свежих nightly флаг -Z json-target-spec удалён; если cargo сообщает о неизвестном флаге, уберите его.

При успешной сборке ELF-файл ядра появится по пути:

kernel/target/i686-perfix/debug/perfix

5. Создание загрузочного ISO

Скрипт tools/build-iso.sh выполняет это автоматически. Вручную шаги выглядят так:

mkdir -p build/iso/boot/grub
cp kernel/target/i686-perfix/debug/perfix build/iso/boot/perfix.elf

Файл build/iso/boot/grub/grub.cfg с конфигурацией загрузки через Multiboot 1:

set timeout=0
set default=0

menuentry "Perfix" {
    multiboot /boot/perfix.elf
    boot
}

Создание ISO:

grub-mkrescue --modules="multiboot" --fonts="" --locales="" --themes="" -o build/perfix-min.iso -d /usr/lib/grub/i386-pc build/iso

Готовый образ будет находиться в build/perfix-min.iso.

6. Запуск в QEMU

Консоль использует VBE-режим 1920×1080×32, который GRUB включает через Multiboot и `gfxpayload`; это даёт 240×67 знакомест при шрифте 8×16. Если режим недоступен, ядро автоматически переходит в VGA text mode 80×25. В VirtualBox нижние 3 строки не используются (фактически 240×64), чтобы приглашение не уходило под край окна.

Запустить ядро без дополнительного тестового диска можно так:

qemu-system-i386 \
    -cdrom build/perfix-min.iso \
    -m 128M

Если прошивка не начинает загрузку с ISO автоматически, укажите порядок загрузки:

qemu-system-i386 \
    -cdrom build/perfix-min.iso \
    -boot order=d \
    -m 128M

Для проверки ATA и экспериментальной работы с exFAT подключите тестовый образ диска:

qemu-system-i386 \
    -drive file=build/perfix-disk.img,format=raw,if=ide,index=0 \
    -cdrom build/perfix-min.iso \
    -boot order=d \
    -m 128M

Образ build/perfix-disk.img используется для тестирования дисковых операций. Он не требуется для обычной загрузки ядра.

7. Возможности ОС

В текущей экспериментальной версии реализованы:

Загрузка через GRUB и Multiboot 1.

Вывод текста в framebuffer-консоль 240×67 (VBE 1920×1080×32, шрифт 8×16); при недоступности режима используется VGA text mode 80×25.

Обработка ввода с PS/2-клавиатуры.

Опрос PS/2-мыши: драйвер читает трёхбайтовые пакеты из контроллера i8042 (без прерываний) и сообщает координаты указателя и состояние кнопок. Команда mouse запускает демонстрацию драйвера.

Командная оболочка.

Текстовый редактор tedit: полноэкранная версия в духе GNU nano для консольной оболочки и GUI-версия в стиле «Блокнота» для pdesk.

GDT и IDT.

Обработчики исключений процессора.

Базовое включение paging с identity mapping первых 4 МиБ.

Чтение секторов ATA PIO.

Драйвер exFAT: монтирование тома, проверка контрольной суммы загрузочного региона, FAT-цепочки и NoFatChain, обход каталогов, чтение и запись файлов, создание и удаление каталогов по произвольному пути, обнаружение разделов exFAT в MBR, extended MBR и GPT.

Определение тома как на диске целиком, так и внутри раздела MBR.

Команды оболочки для работы с exFAT:

mount — параметры смонтированного тома (геометрия, серийный номер, флаги, контрольная сумма);

ls [путь] — список каталога, например ls / или ls SUBDIR;

cat <файл> — вывод содержимого файла (до 13 строк, с переносом длинных строк);

diskinfo — поля загрузочного сектора exFAT;

write <файл> <текст> — создание или перезапись файла;

rm <файл> — удаление файла;

mkdir <каталог> — создание каталога;

rmdir <каталог> — удаление пустого каталога;

cd <каталог> — перейти в каталог;

pwd — показать текущий каталог;

listpart — список разделов (exFAT и ext4) с номером, LBA и размером; диск, отформатированный в exFAT целиком, показывается как раздел 1, поддерживаются MBR, extended MBR и GPT;

cdpart <n> — выбрать раздел по номеру из listpart и перейти в его корень; при загрузке ext4-раздел с установленной системой Perfix подключается автоматически (как и первый раздел exFAT), поэтому cdpart нужен только для остальных разделов;

fetch — сводка: OS, CPU, RAM и свободное место exFAT;

tedit <файл> — текстовый редактор: в консольной оболочке полноэкранный, а в pterm открывает GUI-версию в стиле «Блокнота»;

rootdir — псевдоним ls /, оставлен для совместимости;

mouse — демонстрация драйвера PS/2-мыши: координаты и кнопки обновляются, пока не нажата любая клавиша;

guinit — запустить графическую оболочку pdesk (только в framebuffer-режиме, после выхода управление возвращается в консольную оболочку).

install [n] [format] — установить Perfix на раздел с номером n из listpart; без аргумента выводит список разделов. Без слова format раздел должен быть ext4. Слово format сначала форматирует выбранный раздел в ext4 (все данные на нём стираются), после чего выполняет установку. Команда setup — псевдоним install;

mkfs.ext4 <n> — отформатировать раздел с номером n в ext4, создав пустую файловую систему с каталогом lost+found. Раздел должен быть обычным разделом MBR; контейнер расширенных разделов и GPT отклоняются;

timezone <GMT+N> — задать часовой пояс (смещение локального времени относительно RTC); часовой пояс применяется к часам в доке pdesk и к команде time;

time <dd/mm/yyyy/hh/mm/ss> — установить дату и время в текущем часовом поясе (значение пересчитывается в UTC и записывается в CMOS RTC).

Текущий каталог отображается в приглашении, например `perfix[EN] /docs> `. Команды принимают абсолютные и относительные пути; поддерживаются `.`, `..` и повторные `/`. `cd` без аргумента переходит в корень. Файлы и каталоги можно создавать, перезаписывать и удалять в любом существующем каталоге. Удалить можно только пустой каталог; непустой каталог и обычный файл защищены от неверных операций (rm не удаляет каталог, rmdir не удаляет файл, write не перезаписывает каталог). Тома с размером сектора, отличным от 512 байт, не поддерживаются. Регистр ASCII в именах не учитывается. Имена, содержащие не-ASCII символы, выводятся с символами ?. Каталоги не расширяются автоматически: когда в выделенном кластере заканчиваются свободные слоты, создание нового элемента возвращает `no free space`. Стрелки вверх/вниз листают историю последних 16 команд; набранный, но не выполненный текст сохраняется и возвращается при возврате из истории.

Редактор tedit

tedit открывает файл в полноэкранном режиме: строка заголовка, 64 строки текста, строка состояния и подсказка по клавишам. Длинные строки переносятся, курсор и экран прокручиваются. Отсутствующий файл открывается как новый.

Горячие клавиши:

Ctrl+O — сохранить файл (текст записывается в UTF-8);

Ctrl+X — выход; при наличии изменений редактор спрашивает Y/N, сохранять ли буфер;

Ctrl+K — вырезать текущую строку;

Ctrl+U — вставить вырезанную строку;

Ctrl+G — подсказка по клавишам;

стрелки, Home, End, PageUp, PageDown — перемещение курсора;

Backspace, Delete, Enter, Tab — редактирование (Tab вставляет четыре пробела).

Ограничения tedit: буфер 8 КиБ, поддерживаются символы CP866 (ASCII и русская кириллица); остальные символы при загрузке заменяются на ?.

В окне pterm команда tedit открывает графическую версию редактора: белое поле текста, строку меню (File, Edit, Format, View, Help), строку состояния с номером строки и столбца и полосу прокрутки — по виду как «Блокнот» Windows. Пункты меню кликабельны и открывают выпадающие списки: File — Save, Save As... (Ctrl+S) и Exit, Edit — Cut line и Paste, Format — включение и выключение переноса строк, View — показ строки состояния, Help — подсказка по клавишам и сведения о редакторе. Save As открывает диалог с полем «File name», где можно ввести абсолютный или относительный путь, например `/test/test.txt`; Enter сохраняет, Esc отменяет. Горячие клавиши те же, что у консольного tedit (Ctrl+O, Ctrl+X, Ctrl+K, Ctrl+U, Ctrl+G), курсор ставится и мышью. При закрытии окна с несохранёнными изменениями редактор спрашивает Y/N/Ctrl+C. Заголовок окна показывает имя файла и звёздочку при несохранённых изменениях. Команда tedit без аргумента открывает пустой документ `untitled`; сохранить его нельзя, пока не открыт файл командой `tedit <файл>`. Консольный tedit в самой оболочке (без pterm) по-прежнему работает в полноэкранном режиме.

Графическая оболочка pdesk

pdesk — ранняя версия графической оболочки Perfix. Она собирается отдельным crate-ом в каталоге pdesk/ и не зависит от внутренностей ядра: всё взаимодействие идёт через трейт pdesk::Platform, который реализован в kernel/src/gui.rs поверх framebuffer-консоли, клавиатуры и PS/2-мыши.

Пока в оболочке есть рабочий стол, пять приложений (терминал pterm, тетрис, змейка, редактор tedit и установщик Perfix), указатель мыши и док в стиле macOS. На уже установленной системе установщик скрыт из дока и меню. Каждое приложение открывается в своём окне: окна перетаскиваются за заголовок левой кнопкой, а справа в заголовке — кнопки в стиле Windows (свернуть, развернуть на весь экран / восстановить, закрыть). Активное окно получает клавиатуру и рисуется поверх остальных. Закрытое или свёрнутое окно открывается кликом по иконке приложения в доке или через меню перфоратора; при закрытии терминал начинает новую сессию. Выход из pdesk — Ctrl+Q, команда exit или пункт Exit to shell в меню дока; управление возвращается в консольную оболочку.

Док прижат к нижнему краю по центру и расширяется при добавлении приложений: его ширина считается по количеству иконок. Справа в доке показываются текущие время и дата из CMOS RTC (с учётом часового пояса, обновляются автоматически). Крайняя левая иконка — перфоратор (лончер): по нажатию над доком открывается меню со всеми GUI-приложениями (pterm, tetris, snake, tedit, install), кнопкой Shutdown (выключение через ACPI) и пунктом Exit to shell. Иконки и пункты меню подсвечиваются при наведении, клик мимо меню закрывает его, а перетаскивание окна начинается только за его заголовок.

Тетрис: поле 10x20, стрелки — движение и поворот, пробел или Enter — сброс фигуры, после проигрыша Enter начинает заново. Змейка в духе Nokia 3310: поле 20x20 на «LCD», стрелки задают направление, движение начинается с первой стрелки, после проигрыша — Enter.

pterm выполняет настоящие команды оболочки Perfix: help, version, fetch, ls, cat, write, rm, mkdir, rmdir, cd, pwd, calc, cp, mv, mount, diskinfo, listpart, cdpart и другие — код команд и файловых систем не дублируется в pdesk. Ядро запускает команду в виртуальной консоли 80x40 и передаёт её текст в окно (kernel/src/pterm.rs), а приглашение в pterm показывает активную раскладку и текущий каталог.

Полноэкранные команды (mouse, divzero, pagefault, halt) получают настоящий экран целиком: оболочка временно убирает рабочий стол, после завершения команды pdesk перерисовывается. Команда tedit перехватывается окном и открывает GUI-редактор, поэтому консольный полноэкранный tedit в pterm не запускается; в консольной оболочке без pdesk он работает как раньше. Команда guinit из pterm запрещена, чтобы не запустить оболочку рекурсивно, а clear и exit обрабатываются самим окном.

Ранняя версия не запускается автоматически: в консольной оболочке введите guinit. Для запуска нужен линейный framebuffer (GRUB настраивает 1920x1080x32); в VGA text mode команда сообщает, что графика недоступна.

Установка на диск

Установочный ISO загружает в память три Multiboot-модуля: ядро perfix.elf, первый сектор GRUB boot.img и сгенерированный core.img. Установить Perfix можно из консоли командой install [n] [format] (псевдоним setup [n] [format]) или в pdesk через приложение install. Установщик копирует ядро в корень выбранного раздела как /perfix.elf, записывает boot.img в MBR и core.img сразу после MBR по LBA 1. Сигнатура диска и таблица разделов при этом сохраняются. core.img ищет /perfix.elf через search --file, поэтому номер раздела не зашивается в загрузчик.

Без слова format установка идёт только на существующий ext4-раздел. Явный флаг format (в pdesk — переключатель «Format as ext4») сначала создаёт на выбранном разделе новую ext4-ФС, стирая его содержимое, и только затем устанавливает Perfix. Отдельная команда mkfs.ext4 <n> форматирует раздел, не выполняя установку. Форматирование поддерживает разделы от нескольких мегабайт; для разделов меньше 8 МиБ используется размер блока 1 КиБ, иначе 4 КиБ.

Принимаются только MBR-диски: GPT (защитный MBR с типом 0xEE) отклоняется. Контейнер расширенных разделов нельзя ни установить как цель, ни отформатировать. Первый раздел должен начинаться после конца core.img — для обычного начала на LBA 2048 места достаточно; если промежуток после MBR меньше, установка не выполняется. Ядро записывается раньше загрузчика, чтобы ошибка на раннем этапе не испортила существующую загрузку.

После успешной установки на ext4-разделе создаётся файл /etc/InstallSuccess. При загрузке с диска (когда установочные Multiboot-модули отсутствуют) система проверяет этот маркер и убирает установщик из консоли (команды install и setup) и из pdesk (иконка и пункт меню install). На установочном ISO установщик остаётся доступным, даже если на подключённом диске уже есть Perfix.

Оболочку можно собрать отдельно от ядра и ISO:

```bash
cargo +nightly build --manifest-path pdesk/Cargo.toml \
    --target kernel/i686-perfix.json -Z build-std=core -Z json-target-spec
```

Результат — pdesk/target/i686-perfix/debug/libpdesk.rlib. При сборке ISO через tools/build-iso.sh ядро собирает pdesk автоматически как path-зависимость.

Проверка драйвера exFAT на хосте

Драйвер файловой системы вынесен в kernel/src/exfat/fs.rs и не зависит от ATA и VGA: доступ к диску выполняется через трейт BlockReader. Благодаря этому его можно проверять обычными тестами на хосте, подставляя образ диска в памяти. Тесты лежат в tools/exfat-check и компилируют тот же файл драйвера, что и ядро.

Запуск проверки:

cargo test --manifest-path tools/exfat-check/Cargo.toml

Тесты покрывают монтирование тома, определение раздела MBR, проверку контрольной суммы загрузочного региона, разбор наборов записей каталога, FAT-цепочки, режим NoFatChain, чтение и запись файлов, создание и удаление каталогов, защиту непустых каталогов и обработку повреждённых структур.



8. Ограничения

Perfix — учебный проект, а не готовая операционная система общего назначения.

Основной проверенной средой запуска является QEMU. Совместимость с реальным оборудованием, включая старые процессоры, необходимо проверять отдельно.

Перед экспериментами с реальными накопителями используйте тестовые образы и резервные копии.

Установщик работает только с MBR-дисками, требует свободного промежутка после MBR для core.img и изменяет MBR, поэтому на реальном накопителе с другой загрузочной записью его нужно применять осознанно. Форматирование (install ... format или mkfs.ext4) необратимо уничтожает данные выбранного раздела.
