# Perfix — сборка ядра

Perfix — экспериментальное 32-битное ядро операционной системы для архитектуры x86, написанное на Rust без стандартной библиотеки (`no_std`). Загрузка выполняется через GRUB с использованием Multiboot 1.

Это руководство описывает сборку и запуск Perfix на Linux с использованием CachyOS, Rust nightly, GRUB и QEMU.

## 1. Требования

Для сборки потребуются:

- Linux x86-64
- Rust и Cargo через rustup
- Rust nightly и компонент `rust-src`
- NASM
- GNU binutils
- GRUB и `grub-mkrescue`
- xorriso
- QEMU с поддержкой i386

В Arch-based дистрибутиве установите необходимые системные инструменты через `pacman`. Названия пакетов QEMU и GRUB могут зависеть от состава репозиториев:

```bash
sudo pacman -S --needed rustup rust-src nasm binutils grub xorriso
```

Установите QEMU, если он ещё не установлен, выбрав пакет с поддержкой системной эмуляции i386.

Если системный пакет Rust конфликтует с rustup, не устанавливайте их вслепую одновременно: используйте одну согласованную установку Rust.

## 2. Настройка Rust

Установите nightly toolchain:

```bash
rustup toolchain install nightly
rustup component add rust-src --toolchain nightly
```

Проверьте установку:

```bash
rustc +nightly --version
cargo +nightly --version
```

Perfix использует собственную конфигурацию цели `kernel/i686-perfix.json`, поэтому для сборки применяется nightly Cargo с флагом `-Z json-target-spec`.

## 3. Получение исходников

Клонируйте репозиторий:

```bash
git clone https://github.com/Densikasrv/perfix
cd perfix
```

Посмотрите структуру проекта:

boot/ — загрузочный код на ассемблере.

kernel/src/ — исходный код ядра на Rust.

kernel/linker.ld — сценарий компоновщика.

kernel/i686-perfix.json — конфигурация цели компиляции.

pdesk/ — графическая оболочка Perfix; отдельный crate (`pdesk`), который ядро подключает как path-зависимость.

build/ — каталог для сборочных артефактов.

4. Сборка ядра

Все шаги сборки выполняет скрипт tools/build-iso.sh: он собирает объектные файлы загрузчика через NASM, собирает ядро nightly-компилятором с -Z build-std=core и создаёт ISO через grub-mkrescue.

bash tools/build-iso.sh

Готовый образ появится в build/perfix-min.iso. Скрипт сам подставляет абсолютные пути в RUSTFLAGS, поэтому каталог репозитория может быть любым, а запускать его можно из любой директории.

Ручная сборка

Соберите объектные файлы загрузчика:

mkdir -p kernel/target
nasm -f elf32 boot/boot.asm -o kernel/target/boot.o
nasm -f elf32 boot/gdt.asm -o kernel/target/boot-gdt.o
nasm -f elf32 boot/idt.asm -o kernel/target/boot-idt.o
nasm -f elf32 boot/exec.asm -o kernel/target/boot-exec.o

Затем задайте RUSTFLAGS и соберите ядро (пример для bash, из корня репозитория):

export RUSTFLAGS="-C link-arg=-T$PWD/kernel/linker.ld -C link-arg=-m -C link-arg=elf_i386 -C link-arg=$PWD/kernel/target/boot.o -C link-arg=$PWD/kernel/target/boot-gdt.o -C link-arg=$PWD/kernel/target/boot-idt.o -C link-arg=$PWD/kernel/target/boot-exec.o"

cargo +nightly build --manifest-path kernel/Cargo.toml -Z build-std=core -Z json-target-spec --target kernel/i686-perfix.json

Учтите: RUSTFLAGS содержит абсолютные пути, вычисленные через $PWD, поэтому команды нужно выполнять из корня репозитория. В fish многострочная вставка без обратного слэша ломается на отдельные команды — используйте одну строку или запускайте скрипт. В свежих nightly флаг -Z json-target-spec удалён; если cargo сообщает о неизвестном флаге, уберите его.

При успешной сборке ELF-файл ядра появится по пути:

kernel/target/i686-perfix/debug/perfix

5. Создание загрузочного ISO

Скрипт tools/build-iso.sh выполняет это автоматически. Вручную шаги выглядят так:

mkdir -p build/iso/boot/grub
cp kernel/target/i686-perfix/debug/perfix build/iso/boot/perfix.elf

Файл build/iso/boot/grub/grub.cfg с конфигурацией загрузки через Multiboot 1:

set timeout=0
set default=0

menuentry "Perfix" {
    multiboot /boot/perfix.elf
    boot
}

Создание ISO:

grub-mkrescue --modules="multiboot" --fonts="" --locales="" --themes="" -o build/perfix-min.iso -d /usr/lib/grub/i386-pc build/iso

Готовый образ будет находиться в build/perfix-min.iso.

6. Запуск в QEMU

Консоль использует VBE-режим 1920×1080×32, который GRUB включает через Multiboot и `gfxpayload`; это даёт 240×67 знакомест при шрифте 8×16. Если режим недоступен, ядро автоматически переходит в VGA text mode 80×25. В VirtualBox нижние 3 строки не используются (фактически 240×64), чтобы приглашение не уходило под край окна.

Запустить ядро без дополнительного тестового диска можно так:

qemu-system-i386 \
    -cdrom build/perfix-min.iso \
    -m 16M

Если прошивка не начинает загрузку с ISO автоматически, укажите порядок загрузки:

qemu-system-i386 \
    -cdrom build/perfix-min.iso \
    -boot order=d \
    -m 16M

Для проверки ATA и экспериментальной работы с exFAT подключите тестовый образ диска:

qemu-system-i386 \
    -drive file=build/perfix-disk.img,format=raw,if=ide,index=0 \
    -cdrom build/perfix-min.iso \
    -boot order=d \
    -m 16M

Образ build/perfix-disk.img используется для тестирования дисковых операций. Он не требуется для обычной загрузки ядра.

16 МиБ RAM достаточно для консоли, pdesk/pterm и запуска статических glibc-программ: буфер ELF-файла и стек программы выделяются из свободной памяти только на время запуска, куча программы отображается по мере роста `brk`, а отладочные секции не попадают в загрузочный образ. При 8 МиБ консоль и небольшие программы тоже работают, но запас памяти почти исчерпан, поэтому для полноценной работы рекомендуется не меньше 16 МиБ. В консольном режиме при 6 МиБ работают оболочка, Perfbrowse и установка небольших пакетов pfpak.

7. Возможности ядра

В текущей экспериментальной версии реализованы:

Загрузка через GRUB и Multiboot 1.

Вывод текста в framebuffer-консоль 240×67 (VBE 1920×1080×32, шрифт 8×16); при недоступности режима используется VGA text mode 80×25.

Обработка ввода с PS/2-клавиатуры, английская и русская раскладки (переключение — правый Ctrl или Alt+Shift).

Опрос PS/2-мыши: трёхбайтовые пакеты, координаты указателя и кнопки. Прерывания не используются, драйвер читает данные из контроллера i8042 в основном цикле; команда mouse запускает демонстрацию драйвера.

Русские буквы выводятся в кодовой странице CP866: глифы кириллицы загружаются в знакогенератор VGA при старте ядра.

Командная оболочка.

GDT и IDT.

Обработчики исключений процессора.

Базовое включение paging с identity mapping первых 4 МиБ.

Чтение секторов ATA PIO.

Драйвер exFAT: чтение и запись файлов, создание и удаление каталогов по произвольному пути, обнаружение разделов exFAT в MBR, extended MBR и GPT.

Определение тома как на диске целиком, так и внутри раздела MBR.

Команды оболочки для работы с exFAT:

mount — параметры смонтированного тома (геометрия, серийный номер, флаги, контрольная сумма);

ls [путь] — список каталога, например ls / или ls SUBDIR;

cat <файл> — вывод содержимого файла (до 13 строк, с переносом длинных строк); текст в UTF-8 перекодируется в CP866, поэтому кириллица видна;

diskinfo — поля загрузочного сектора exFAT;

rootdir — псевдоним ls /, оставлен для совместимости;

guinit — запустить графическую оболочку pdesk (нужен framebuffer-режим);

elev <команда> — выполнить одну команду с правами суперпользователя после ввода его пароля; при удалении системных файлов выводится предупреждение `Do you know what you're doing? [Y/N]`;

install [n] [format] — установить Perfix на раздел с номером n из listpart; без аргумента выводит список разделов. Без слова format раздел должен быть ext4; с format раздел сначала форматируется в ext4 (данные теряются). Команда setup — псевдоним install;

mkfs.ext4 <n> — отформатировать обычный раздел MBR с номером n в ext4 (создаётся пустая ФС и lost+found); контейнер расширенных разделов и GPT не принимаются;

timezone <GMT+N> — задать часовой пояс (смещение локального времени относительно RTC); применяется к часам в доке pdesk и к команде time;

time <dd/mm/yyyy/hh/mm/ss> — установить дату и время в текущем часовом поясе (пересчитывается в UTC и пишется в CMOS RTC);

mouse — демонстрация драйвера PS/2-мыши: координаты и кнопки обновляются, пока не нажата любая клавиша;

charset — таблица CP866 для проверки загруженного шрифта (диагностика кириллицы);

write <файл> <текст> — создать или перезаписать файл по указанному пути; текст сохраняется в UTF-8. Обычный пользователь может писать только в свой домашний каталог и `/tmp`, системные пути требуют `elev`;

rm <файл> — удалить файл и освободить его кластеры;

mkdir <каталог> — создать каталог;

rmdir <каталог> — удалить пустой каталог;

cd <каталог> — сменить текущий каталог;

pwd — показать текущий каталог;

listpart — список разделов (exFAT и ext4) с номером, LBA и размером; диск, отформатированный в exFAT целиком, показывается как раздел 1, поддерживаются MBR, extended MBR и GPT;

cdpart <n> — выбрать раздел по номеру из listpart и перейти в его корень; при загрузке ext4-раздел с установленной системой Perfix подключается автоматически (как и первый раздел exFAT), поэтому cdpart нужен только для остальных разделов;

fetch — сводка: OS, CPU, RAM и свободное место exFAT;

tedit <файл> — текстовый редактор: в консольной оболочке полноэкранный, а в pterm открывает GUI-версию в стиле «Блокнота»;

exec <файл> — запустить сторонний 32-битный ELF-файл (статический ELF32 i386); псевдоним run;

lspci — список устройств PCI: адрес bus:slot.func, vendor:device, класс и IRQ; известные сетевые карты помечаются именами (RTL8139, e1000); псевдоним pci;

net — состояние сетевого интерфейса: модель карты, MAC, IP/маска, шлюз, DNS, состояние линка и счётчики кадров;

ping <a.b.c.d> — четыре ICMP-эхо с ответами и статистикой;

pfpak — пакетный менеджер (list, info, install, remove, update, upgrade); работает поверх ext4 и требует `elev` для изменяющих команд.

Запись реализована для файлов и каталогов в любом существующем каталоге тома: кластеры выделяются непрерывно (флаг NoFatChain), обновляются битовая карта распределения и флаг VolumeDirty, время берётся из CMOS RTC. Новый каталог получает один нулевой кластер; удалить можно только пустой каталог. Каталоги не расширяются автоматически — при заполнении кластера возвращается no free space. Размер текста в write ограничен буфером строки оболочки (256 байт). Тома с размером сектора, отличным от 512 байт, не поддерживаются. Пути абсолютные или относительные, разделяются символом /, поддерживаются . и ..; регистр ASCII и кириллицы CP866 не учитывается. Имена, содержащие символы вне ASCII и русской части CP866, выводятся с символами ?. История команд хранит последние 16 команд; стрелки вверх/вниз листают её, а набранный черновик сохраняется до возврата из истории.

Запуск сторонних ELF-программ

Консольная оболочка и pterm запускают сторонние программы командой `exec <файл>` (псевдоним `run <файл>`). Поддерживаются статические исполняемые файлы ELF32 i386 с типом `ET_EXEC`; динамически слинкованные файлы, PIE и программы другой архитектуры отклоняются с понятным сообщением.

Загрузчик проверяет ELF-заголовок, размещает сегменты `PT_LOAD` по виртуальным адресам, обнуляет BSS и строит стек с `argc`/`argv`/`envp` и полным auxv, как при запуске в Linux. Затем управление передаётся точке входа. Программе доступно адресное пространство кучи размером 8 МиБ по адресу `0x40000000` для `brk` и TLS; физические страницы отображаются по мере роста `brk`, поэтому небольшая программа не занимает все 8 МиБ сразу. Системные вызовы Linux i386 выполняются через `int 0x80`: `exit`/`exit_group`, `write`, `writev`, `brk`, `uname`, `mprotect`, `set_thread_area`, `getpid`, `getuid`/`getgid`/`geteuid`/`getegid`; неизвестный вызов возвращает `-1`. Вывод программы попадает и в консоль, и в pterm.

Программа выполняется в ring 0 без изоляции адресного пространства и TSS, поэтому это не песочница. Исключение CPU внутри программы перехватывается: выводится `exec: program crashed: exception ... at EIP ...`, после чего управление возвращается оболочке.

Сеть

Драйвер RTL8139/RTL810x работает в классическом режиме через порты ввода-вывода: приём по кольцевому буферу, передача через четыре дескриптора TSD, опрос регистров без прерываний. Поверх него реализованы Ethernet, ARP, IPv4, ICMP, UDP, DNS и TCP. Параметры статические, под user-mode сеть QEMU: `10.0.2.15/24`, шлюз `10.0.2.2`, DNS `10.0.2.3`. Адреса вне подсети отправляются через шлюз (MAC шлюза в кадре, IP получателя исходный). Команда `net` показывает MAC, адрес, линк и счётчики; `ping <a.b.c.d>` разрешает адрес через ARP, отправляет четыре ICMP-эха и показывает время отклика в миллисекундах.

Perfbrowse (`browse <url>` или `perfbrowse <url>`) разрешает DNS-имена через A-записи, открывает TCP-соединение и загружает страницу по HTTP/1.0. Ответ читается до закрытия соединения и поддерживает `Transfer-Encoding: chunked`, затем HTML превращается в простой текст с переносом по словам и прокруткой. Поддерживаются URL с `http://`, без схемы, IP-адреса и нестандартные порты; схема распознаётся без учёта регистра. `https://` обслуживается TLS 1.3 (`TLS_AES_128_GCM_SHA256`, X25519): проверяются цепочка сертификатов до встроенных корневых CA, срок действия, subjectAltName и подпись CertificateVerify; поддерживаются подписи RSA (PKCS#1 v1.5/PSS, SHA-256) и ECDSA P-256 (SHA-256). Ограничения текущего этапа: сертификаты на P-384/P-521 и подписи SHA-384/SHA-512 не поддерживаются (часть сайтов отклоняется с `tls: cert: cannot parse issuer`). Своего механизма повторной передачи в TCP нет, но в user-mode сети QEMU потери практически исключены. В pdesk браузер открывается отдельным окном (иконка `www` или команда `browse` в pterm) с адресной строкой, прокруткой и Ctrl+L для очистки адреса. CSS, изображения, таблицы и ссылки не поддерживаются; тело ответа и текст ограничены 32 КиБ. e1000 появится позже.

Пакетный менеджер pfpak

pfpak устанавливает пакеты `.tar.gz` на ext4-раздел с системой. Репозитории перечислены в `/etc/pfpak/repo.list` в формате `http://example.com/perfix/pfpak RELEASE:fatcat`; для релиза `fatcat` манифест и архив пакета лежат по путям `<url>/fatcat/<пакет>/MANIFEST` и `<url>/fatcat/<пакет>/<пакет>-<версия>.tar.gz`. Репозиторий может быть и `https://`: загрузка идёт по TLS 1.3 с проверкой цепочки сертификатов (те же ограничения по P-384/SHA-384, что и у Perfbrowse). Для GitHub указывайте прямой адрес `https://raw.githubusercontent.com/<владелец>/<репозиторий>/<ветка>/pfpak`: его цепочка (RSA/SHA-256) проверяется, а ссылки через `github.com/.../raw/...` не годятся — там 302-редирект на raw-хост, который клиент не выполняет. Адрес с `/tree/` (как его показывает GitHub) тоже принимается: pfpak убирает `/tree/` перед запросом. Необязательный `<url>/fatcat/INDEX` загружается командой `pfpak update`. Установленные манифесты хранятся в `/etc/pfpak/InstalledPaks/<пакет>/MANIFEST`.

Манифест содержит поля `name`, `version`, `maintainer`, `description`, `size`, `depends` и список файлов после `files:`. Зависимости ставятся рекурсивно; удаление пакета, от которого зависят другие, блокируется. `install`, `remove`, `update` и `upgrade` требуют `elev`, а `list` и `info` доступны всем.

Распаковка разрешена только в `/usr`, `/opt`, `/bin`, `/sbin`, `/lib`, `/etc`, `/var` и `/share`; системные файлы защищены. Отклоняются `..`, ссылки, жёсткие ссылки, специальные файлы и файлы, не перечисленные в манифесте. Размеры ограничены: манифест 16 КиБ, отдельный файл 2 МиБ, весь пакет 16 МиБ. При ошибке созданные файлы удаляются. pfpak использует общий HTTP-клиент ядра, поэтому работает и по HTTP, и по HTTPS.

TLS-клиент

Клиент TLS 1.3 живёт в kernel/src/tls (handshake и записи), криптография — в kernel/src/crypto: SHA-256/HMAC/HKDF, AES-128-GCM, X25519, RSA и ECDSA P-256 поверх арифметики Монтгомери. Абсолютно все примитивы проверяются тест-векторами на хосте:

    cargo run --manifest-path tools/crypto-check/Cargo.toml

Корневые сертификаты встроены в kernel/src/tls/roots.bin (79 RSA-корней из системного набора ca-certificates); таблица смещений генерируется tools/gen-roots.py, DER-файл пересобирается той же командой. При проверке цепочки издатель подбирается по DER имени (subject корня = issuer сертификата), после чего проверяется подпись RSA или ECDSA, срок действия по UTC-времени RTC и имя/IP из subjectAltName.

Для локальных испытаний есть отдельный тестовый УЦ — он подключается только при сборке с флагом `dev-root`:

    bash tools/gen-test-pki.sh                 # создаёт /tmp/perfix-tls-pki и kernel/src/tls/dev-root.der
    KERNEL_FEATURES=dev-root bash tools/build-iso.sh
    openssl s_server -accept 4433 -tls1_3 -www \
        -cert /tmp/perfix-tls-pki/server.pem -key /tmp/perfix-tls-pki/server.key

В гостевой системе: `browse https://10.0.2.2:4433/`. Сертификат `wrong.pem` из того же каталога (SAN `wrong.example`) используется для проверки отказа: `browse https://10.0.2.2:4434/` должен вернуть `tls: cert: name mismatch`. Без флага `dev-root` тестовый корень в образ не попадает.

Процессоры без SSE поддерживаются: ядро и программы без SSE/AVX работают нормально, а `OSFXSR`/`OSXMMEXCPT` и XSAVE-состояние включаются только при наличии соответствующих возможностей у CPU (проверка через CPUID). FPU (x87) инициализируется при старте, если он есть. Если программа всё же выполнит SSE-инструкцию на CPU без SSE, ядро перехватит #UD и вернёт управление оболочке.

Примеры: `exec /hello`, `run /home/bob/program`.

Раскладка клавиатуры

Переключение EN/RU — правый Ctrl или Alt+Shift. Активная раскладка и текущий каталог видны в приглашении: perfix[EN] /> или perfix[RU] /docs>.

В русской раскладке используется ЙЦУКЕН и кодовая страница CP866: Shift+3 даёт знак номера (№), Shift+6 — двоеточие, Shift+7 — вопросительный знак. Глифы кириллицы загружаются в знакогенератор VGA из kernel/src/font_cp866.rs; это выборка 8x16 из GNU Unifont 16.0.04 (только кириллица и знак номера).

Имена файлов exFAT хранятся в UTF-16 и при выводе переводятся в CP866, поэтому ls и cat работают с русскими именами.

Команда fetch выводит название и версию ОС, brand string процессора через CPUID, объём RAM из Multiboot memory map и свободное/общее место выбранного тома exFAT (по битовой карте распределения).


Графическая оболочка pdesk

pdesk — ранняя версия графической оболочки Perfix. Она собирается как отдельный crate в каталоге pdesk/ и не обращается к внутренностям ядра напрямую: всё взаимодействие идёт через трейт pdesk::Platform, который реализован в kernel/src/gui.rs поверх framebuffer-консоли, клавиатуры и PS/2-мыши.

Пока в оболочке есть рабочий стол, пять приложений (pterm, тетрис, змейка, редактор tedit и установщик Perfix), указатель мыши и док в стиле macOS. На уже установленной системе установщик скрыт из дока и меню. Окна перетаскиваются за заголовок левой кнопкой; справа в заголовке — кнопки в стиле Windows: свернуть, развернуть на весь экран / восстановить, закрыть. Активное окно получает клавиатуру и рисуется поверх остальных. Закрытое или свёрнутое окно открывается кликом по иконке приложения в доке или через меню перфоратора (при закрытии терминал начинает новую сессию). Выход из pdesk — Ctrl+Q, команда exit или пункт Exit to shell в меню дока.

Док прижат к нижнему краю по центру и расширяется при добавлении приложений (ширина считается по числу иконок); справа в нём показываются время и дата из CMOS RTC с учётом часового пояса. Крайняя левая иконка — перфоратор (лончер): по нажатию над доком открывается меню со всеми GUI-приложениями (pterm, tetris, snake, tedit, install), кнопкой Shutdown (выключение через ACPI) и пунктом Exit to shell. Иконки и пункты меню подсвечиваются при наведении; клик мимо меню закрывает его, перетаскивание окна начинается только за заголовок.

Игры: тетрис (поле 10x20; стрелки — движение и поворот, пробел/Enter — сброс фигуры, Enter после проигрыша — заново) и змейка в духе Nokia 3310 (поле 20x20, движение начинается с первой стрелки, Enter после проигрыша — заново).

Редактор tedit в pdesk выглядит как «Блокнот» Windows: строка меню, белое поле текста, строка состояния и полоса прокрутки. Пункты меню кликабельны: File (Save, Save As..., Exit), Edit (Cut line, Paste), Format (перенос строк), View (строка состояния), Help (клавиши, о программе). Save As (Ctrl+S) открывает диалог ввода пути — абсолютного или относительного, например `/test/test.txt`; Enter сохраняет, Esc отменяет. Сохранены горячие клавиши консольного tedit (Ctrl+O, Ctrl+X, Ctrl+K, Ctrl+U, Ctrl+G); курсор можно ставить мышью, заголовок показывает имя файла и звёздочку при изменениях, закрытие с изменениями спрашивает Y/N/Ctrl+C. `tedit` без аргумента открывает пустой `untitled`, который сохраняется в `/home/<имя>/untitled`; диалог Save As заранее заполняется домашним каталогом. Консольный полноэкранный tedit остаётся доступен в самой оболочке без pdesk.

pterm выполняет настоящие команды оболочки Perfix (help, version, fetch, ls, cat, write, rm, mkdir, rmdir, cd, pwd, calc, cp, mv, mount, diskinfo, listpart, cdpart и остальные): ядро запускает команду в виртуальной консоли 80x40 и передаёт её текст в окно, а приглашение pterm показывает раскладку и текущий каталог. Полноэкранные команды (mouse, divzero, pagefault, halt) получают настоящий экран целиком, после чего рабочий стол перерисовывается; tedit перехватывается окном и открывает GUI-редактор, guinit из pterm запрещён, clear и exit обрабатывает само окно.

Ранняя версия не запускается автоматически: в консольной оболочке введите guinit. Для работы нужен линейный framebuffer (GRUB настраивает 1920x1080x32); в VGA text mode команда вернёт ошибку.

Установка на диск

Установочный ISO загружает в память три Multiboot-модуля: ядро perfix.elf, первый сектор GRUB boot.img и сгенерированный core.img. Установщик доступен из консоли (install [n] [format], псевдоним setup) и в pdesk (приложение install в доке). Он спрашивает имя пользователя (1–16 символов), пароль пользователя и пароль суперпользователя, создаёт `/home/<имя>` и записывает хеши в `/etc/users`. Также установщик создаёт `/etc/pfpak/repo.list` с репозиторием по умолчанию и записывает встроенные корневые сертификаты в `/etc/ssl/certs/ca-certificates.crt`, поэтому HTTPS и pfpak работают и после загрузки с диска. После перезагрузки консоль запрашивает `login:` и `password:`. Установщик копирует ядро в корень выбранного раздела как /perfix.elf, затем записывает boot.img в MBR и core.img сразу после MBR по LBA 1. При этом сохраняются сигнатура диска и таблица разделов, поэтому существующая разметка не меняется. core.img содержит конфигурацию GRUB, которая ищет /perfix.elf через search --file, так что номер раздела в загрузчик не зашивается.

Без слова format установка разрешена только на существующий ext4. С format (в pdesk — флажок «Format as ext4») выбранный раздел сначала форматируется в ext4, что стирает его данные, и только потом выполняется установка. Команда mkfs.ext4 <n> создаёт ext4 без установки. Форматтер пишет суперблок, GDT, bitmap, inode table, корневой каталог и lost+found, не используя journal, metadata_csum, 64bit и flex_bg — только функции, которые драйвер Perfix умеет читать и изменять. Для разделов меньше 8 МиБ выбирается блок 1 КиБ, иначе 4 КиБ; поддерживаются диски с несколькими группами и резервными копиями суперблока.

Принимаются только MBR-диски (защитный MBR с типом 0xEE отклоняется); контейнер расширенных разделов нельзя ни выбрать целью, ни отформатировать. Кроме того, первый раздел должен начинаться после конца core.img; для стандартного начала на LBA 2048 промежутка после MBR достаточно. Установка отказывается работать, если GRUB уже не помещается в этот промежуток. Сначала записывается ядро и только потом загрузчик, чтобы ранняя ошибка записи не испортила существующую загрузку.

После успешной установки создаётся файл /etc/InstallSuccess на ext4-разделе. При загрузке с диска без установочных Multiboot-модулей ядро находит этот маркер и скрывает установщик: команды install и setup пропадают из справки и начинают отвечать Unknown command, а иконка и пункт install исчезают из дока и меню pdesk. Установочный ISO по-прежнему показывает установщик.

Отдельная сборка оболочки без ядра и без ISO:

```bash
cargo +nightly build --manifest-path pdesk/Cargo.toml \
    --target kernel/i686-perfix.json -Z build-std=core -Z json-target-spec
```

Готовая библиотека появится в pdesk/target/i686-perfix/debug/libpdesk.rlib. При обычной сборке ISO (tools/build-iso.sh) ядро собирает pdesk автоматически как path-зависимость.

Проверка драйвера exFAT на хосте

Драйвер файловой системы вынесен в kernel/src/exfat/fs.rs и не зависит от ATA и VGA: доступ к диску выполняется через трейт BlockReader. Благодаря этому его можно проверять обычными тестами на хосте, подставляя образ диска в памяти. Тесты лежат в tools/exfat-check и компилируют тот же файл драйвера, что и ядро.

Запуск проверки:

cargo test --manifest-path tools/exfat-check/Cargo.toml

Тесты покрывают монтирование тома, определение раздела MBR, проверку контрольной суммы загрузочного региона, разбор наборов записей каталога, FAT-цепочки, режим NoFatChain, чтение файлов и обработку повреждённых структур.



8. Ограничения

Perfix — учебный проект, а не готовая операционная система общего назначения.

Основной проверенной средой запуска является QEMU. Совместимость с реальным оборудованием, включая старые процессоры, необходимо проверять отдельно.

Перед экспериментами с реальными накопителями используйте тестовые образы и резервные копии.

Установщик поддерживает только MBR-диски (GPT отклоняется). Без format раздел должен быть ext4; с format или через mkfs.ext4 создаётся новая ext4-ФС, а данные раздела безвозвратно теряются. Для core.img нужен свободный промежуток после MBR; на дисках, где первый раздел начинается слишком рано, установка не выполняется. Установка изменяет MBR и секторы после него, поэтому на реальном накопителе с другой загрузочной записью её нужно делать осознанно.
